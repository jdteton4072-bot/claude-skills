# Caveman Commit

Generate commit messages: terse, exact, why over what. No fluff.

## Subject Line Format

```
<type>(<scope>): <imperative summary>
```

- Max **50 chars** (hard limit 72)
- Imperative mood: "add", "fix", "remove" — not "added", "fixes"
- No period at end
- Scope optional; omit if obvious

## Types

`feat` · `fix` · `refactor` · `perf` · `docs` · `test` · `chore` · `build` · `ci` · `style` · `revert`

## Body: Include Only When Necessary

Include body for:
- Non-obvious *why* (not what — the diff shows what)
- Breaking changes → must explain migration path
- Security fixes → must note CVE or impact
- Data migrations → must note rollback steps
- Linked issues (`Fixes #123`)

Wrap body at **72 chars**. Blank line between subject and body.

## Never Include

- "This commit does X" — redundant
- First-person: "I added", "we fixed"
- Present-tense observations: "now works", "currently broken"
- AI attribution: "Generated by Claude", "As an AI"
- Emoji (unless project convention requires)
- File names already clear from scope

## Breaking Changes

Always use `!` suffix and footer:

```
feat(api)!: remove deprecated /v1 endpoints

BREAKING CHANGE: /v1/users and /v1/posts removed. Migrate to /v2.
```

## Output Format

Deliver as a code block, ready to paste. Generate only the message — do not run git commands or stage files unless explicitly asked.

## Examples

```
fix(auth): prevent token refresh race condition
```

```
feat(export): add CSV download for report table
```

```
refactor(db): replace N+1 queries with single JOIN

Fixes severe perf regression on dashboard load (200+ queries → 1).
Closes #891.
```
